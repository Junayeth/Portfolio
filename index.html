How I work

Three things I believe about IT

01
Documentation is a product, not a chore.
Runbooks, onboarding checklists, incident post-mortems — I write them because I've seen what happens when they don't exist. Good documentation means the organisation keeps working when I'm not there. That's the test I apply to everything I write down.
02
Security is an enabler, not a blocker.
The best security posture is one that people don't have to work around. MFA that integrates seamlessly. Access reviews that don't interrupt the business. Policies that explain the why, not just the what. Done right, compliance builds trust — with customers, partners, and inside the organisation.
03
Automate the repetitive, own the complex.
User provisioning, SLA alerts, access deprovisioning — these should happen without a human deciding to do them. That frees IT to focus on the problems that actually require judgment: architectural decisions, vendor evaluations, the edge cases that automation can't handle.

I'm comfortable being the only person who understands both the technical depth and the business context. I write documentation people actually read. I run processes that don't fall apart when I'm on holiday. I believe IT should be an enabler of growth, not a bottleneck it has to work around.
